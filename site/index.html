How it works

From one project to the next in three steps

The component travels with its template, styles, state and methods. The project that receives it doesn't need a build step.

3 calls

0 builds

Define the component

Write a template, styles and methods with builder.define(). It's registered on the page straight away.

Export it

builder.export() turns it into JSON, or a standalone script that doesn't need the library.

Import it in Project B

builder.import() loads it from a file, a URL or your server, and the element is ready to use.

Three ways to share

Pick how the component travels

Use whichever fits how your projects are set up. You can mix them.

Send the JSON

Export the component as data, then import it in the other project. Commit the file, serve it from a CDN, or paste it in. Both projects use this library.

Good for projects you control 
// Project A
const { data } = await builder.export('tally-counter');
// save data as tally-counter.json

// Project B
await builder.import('/components/tally-counter.json');

Ship a standalone script

Export a single .js file that registers the element by itself. The other project doesn't install anything, so it works in any site, CMS or framework.

Good for sites you don't control 
// Project A, e.g. in a build script
const js = await builder.export('tally-counter', { type: 'script' });
fs.writeFileSync('tally-counter.js', js);

<!-- Anywhere else -->
<script src="tally-counter.js"></script>
<tally-counter label="Coffees today"></tally-counter>

Use your own component server

Point apiEndpoint at a server with two routes, then save and load components by name across every project on your team.

Good for a team library 
const builder = new ComponentBuilder({
  apiEndpoint: 'https://components.example.com/api'
});

// POST /components
await builder.export('tally-counter', { type: 'cloud' });

// GET /components/tally-counter
await builder.import('tally-counter');
Before you share

Three rules keep shared components working

Components travel as source text. That keeps them small and framework-free.

  • Keep functions self-contained

    Templates and methods can't use variables or imports from the file they were written in. Those don't exist in the project that imports the component.

  • Only import from sources you trust

    Importing runs the component's code, the same as adding a script tag.

  • Escape what users type

    Props aren't escaped for you. Wrap anything that could contain user input in escape(), which every template receives.
